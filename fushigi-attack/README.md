# Fushigi：方向別の基準絵から作った攻撃モーション01

8方向それぞれの基準絵を、その方向の画像生成時に個別に参照して作成した攻撃です。
左右反転や別方向の絵の流用で済ませていません。開始・終了の身体画像は、承認された基準絵と画素単位で同じです。

## まず見る

- `SW-attack-with-sword.gif`：斜め前SWを、別画像の剣付きで拡大再生。
- `SW-weapon-check.png`：振りかぶり・斬り下ろし・振り抜き・戻しの4ポーズに実際に剣を重ねた確認画像。
- `attack-8directions.gif`：ゲーム内の標準サイズに合わせた8方向の剣付き再生。
- `preview.html`：方向・速度・コマを切り替え、基準絵と比較する確認画面。画像を内蔵しているのでHTML単体で動きます。
- `game-attack.html?testWeapon=1`：実ゲームでの素振り確認。フォルダー内でHTTPサーバーを起動して開きます。

```sh
python -m http.server 8000
# http://localhost:8000/game-attack.html?testWeapon=1
```

町の何もない場所でAttack／Zキーを押すと素振りします。既存の町の入口や倉庫では元の「決定」の動作が優先されます。

## コマと時間

| コマ | 身体の絵 | 時間 |
|---|---|---:|
| 0 | 基準絵そのもの | 35ms |
| 1 | 振りかぶり | 70ms |
| 2 | 斬り下ろし | 40ms |
| 3 | 振り抜き | 55ms |
| 4 | 戻し | 60ms |
| 5 | 基準絵そのもの | 40ms |
| 合計 | | 300ms |

新規画像は4ポーズ×8方向＝32枚。開始・終了を含む表示用は6コマ×8方向です。
GIFでは攻撃後に少し待機して繰り返します。ゲーム側は1回再生して待機に戻します。

## 基準絵の扱い

`assets/hero-base/<方向>.png` が基準絵、`reference-manifest.json` が方向ごとの参照画像とSHA-256です。
各方向の生成に使ったのは、その方向の基準絵と、その方向の4ポーズガイドです。
S、SW、W、NW、N、NE、E、SEをそれぞれ独立した生成リクエストで作成しました。
元の基準絵フォルダーは上書きしていません。

全コマ256×256 RGBA、足元の基準は(128,224)、頭頂から接地基準まで192pxを基準とします。
ゲームではこの192pxを身長1.5マス（1マス64pxなら96px）に対応させます。
新規コマの画像位置は同方向の頭を参照した照合と、靴の位置への平行移動で合わせています。
身体・腕を画像変形で動かしたり、中間絵をモーフィングで作ったりしていません。
姿勢に応じた頭・胴の上下動や細部差は残ります。

## 3・4コマ目の武器について

最初の仮の設定では、SWの4コマ目で剣が髪の裏に隠れ、戻しとして不自然でした。
画像の手の位置を調べ、握り座標に加えて角度・前後関係を調整し直しています。

- 3コマ目：手を身体の前で交差させ、剣を下・右方向へ振り抜く配置。
- 4コマ目：手を戻しながら、剣を頭の外側へ上げる角度。手前描画にして髪の裏へ抜ける表示を避ける。
- 右手の握り部分を前景として重ね、柄が手の表面に貼り付いて見えるのを抑える。

`SW-weapon-check.png` はこの修正後の実合成です。剣を身体画像の中に描き込んだものではありません。
今回確認したのは検証用の片手剣です。武器の種類を変える場合は、画像側の柄の位置や大きさ・見える面も合わせる必要があります。

## 装備の情報

`assets/hero-attack/attack.json` に方向・コマごとの以下の情報があります。

- 本人の右手（武器）・左手（盾）の握り位置。
- 武器の角度と見かけの長さ。
- 装備を身体の手前／奥に描く指定。
- 右手の簡易前景マスク。

`art-space-calibration.json` と `calibrate_attack.py` に実画像を見て合わせた値があります。
隠れた遠い手の位置は一部推定です。前景マスクは簡易な楕円で、精密な指や前腕全体の切り抜きではありません。
剣の角度はコマ単位で切り替えます。連続的な3D回転の再現や全武器の握りを保証するものではありません。

盾の仮重ねも切り替えられますが、振り抜く右腕が盾の前を通る箇所などの完全な隠れ方は今後の調整が必要です。
製品用の盾の向き別画像や、手・前腕の精密なマスクは今回の完成範囲に含めていません。

## ゲームへの差し込み

`hero-base-renderer.js`、`hero-attack-renderer.js` と2種類のアセットフォルダーを使います。
ローカル確認用の本体は `game-attack.html`、元の本体は `game-original.html`、差分は `integration.patch`。
元リポジトリの作業コピーに適用する際は、JSとアセットをコピーしたうえで `git apply --check integration.patch` を実行してください。

`player.swing` の既存300msに合わせて再生します。攻撃開始時の向きを記録し、途中で向きの入力が変わっても同じ攻撃の絵が別方向へ飛ばないようにしています。
ダメージ確定、敵のターン、命中演出の発生時刻などのゲームロジックは元の処理を維持しています。描画の斬り下ろし開始は105msなので、命中演出との細かな同期は今後の調整対象です。
連続入力では既存どおり攻撃の時計が再設定され、前の攻撃が途中で切り替わる場合があります。

仮の剣の表示はクエリ `testWeapon=1` で明示的に有効にする確認機能です。持ち物の武器名・盾名と完成アートを連動する実装はまだ追加していません。
歩行・被弾・死亡の新しい方向別アニメーションも今回の追加対象ではありません。移動時は方向別の基準絵で動きます。
GitHubへのpush・Pagesへの公開はしていません。

## 検証結果

- 8方向の基準参照を記録。開始・終了の画像が基準絵と完全一致することを検査。
- 32個の新規ポーズが相互に異なること、画像寸法・透過・端の切れを検査。
- 靴の最下端は同方向の基準絵から0〜1pxの範囲に揃うことを検査。
- 8方向×4ポーズ×3サイズ＝96パターンで、別画像の剣・盾の柄と指定ソケットが一致することをブラウザの変換行列で検査。192個の装備接続点。
- ゲーム内で300ms後の待機復帰と、攻撃中の向きの固定を確認。
- 横844×390・縦390×844、町・洞窟で表示確認。JavaScriptのページエラーなし。
- 既存MVPテストの結果は `mvp-validation.txt`。

座標一致の検査は、手首の描写や全装備の見た目の正しさを自動判定するものではありません。実合成の画像と再生を別途確認しています。

## 再制作

```sh
LP_NUM_THREADS=2 blender -b -t 4 --python make_attack_guides.py
python prepare_attack_guides.py
# 各方向の基準絵＋同方向ガイドを使い、生成した2×2画像を generated/<方向>.png に配置
python prepare_attack_assets.py S SW W NW N NE E SE
python calibrate_attack.py
python build_attack_preview.py
python integrate_attack.py
```

参照用の3Dマネキンとコード、元の生成画像、ガイド画像も保存しています。画像生成は別途必要です。
