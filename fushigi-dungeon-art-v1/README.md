# 自然洞窟の生成画像・本番適用 v1

確認: https://yyvape-dev.github.io/Fushigi/fushigi-dungeon-v1/random-review.html

本編: https://yyvape-dev.github.io/Fushigi/

画像生成から本番適用まで実施。床3原画、岩壁上面・正面、下り階段の6セルを生成し、穏やかな床へ1回修正した。原画とプロンプト、切り出し座標・SHA256、再現スクリプトを保存。

## 制作と接続

- `source-art/cave-atlas-initial.png`：初回原画。
- `source-art/cave-atlas.png`：床の大きな亀裂・明暗を抑えた採用原画。
- `generation-record.json`：画像生成と床修正のプロンプト・参照元。
- `build.py` / `asset-record.json`：3列×2行のアトラスから4pxの境界余白を除いて切り出し、256px WebPへ。原画の描き直しや色補正はしない。配信画像6枚の合計は約141KB。
- `../assets/cave-terrain.js`：床を共通境界へ合成し、壁の上下左右4方向と斜め4方向の隣接情報から内外角・端部を描く。壁の模様は2マスにわたる原画を連続サンプリングし、鏡合わせにしない。全描画は当該セル内に収め、判定を変えない。

床の共通下地はテクスチャを反転リピートして境界を一致させ、床差分は内側だけ合成する。キャラ・装備の画像を反転しているという意味ではない。階段は外縁だけ共通床へなじませ、踏み段を保持する。壁の内外角は生成した岩画像と地形に基づく描画マスクの組み合わせで、256枚の角原画を個別生成したものではない。

従来の矩形タイルの縁線と壁用の追加陰影は新画像に重ねず、視界・既探索範囲の明暗と床の壁際の影は維持。通常・乾燥・青岩の3色調で同じ素材を使う。

## 検証

`python -m http.server 8001 --bind 127.0.0.1` で配信し、`python fushigi-dungeon-art-v1/check.py`。Playwright・システムChromiumが必要。

- 壁16方向マスク×斜め16通り＝256接続。
- 異なる床差分同士の共有境界は3色調とも画素差0。
- 40生成階で描画前後のマップが一致し、各部屋へ到達可能。
- 幅1マス通路、L字の角、階段、横・縦画面、画像6枚の読込とブラウザエラーなし。
- 既存MVP一式と200階の配置・店売買検証もALL OK。
- 最初の固定部屋の確認ページも新画像を標準とし、旧石室への比較切替を検証。

結果は `validation.json`、実画面は `game-landscape.png`、`corridor.png`、`stairs.png`、`game-portrait.png`、接続一覧は `wall-connections.png`。

キャラ・武器・盾とゲームの生成・戦闘・店の仕様は変更していない。今回は地形の見た目の更新で、敵・落ち物の未制作画像や店主の制作は含まない。
