## 固定する設計

- 1マスを1ワールド単位。壁高は約1.1〜1.9、床ピッチ0.94の直交投影。これは本家の測定値ではない。
- カメラ・光・材質の規格を共有し、上面と側面を一つのメッシュから書き出す。
- 上面は2×2マス周期の連続した高さ場。世界座標を共有する辺は同じ頂点を使い、16近傍パターンで個別に角の絵を生成しない。
- 北・東・南・西の隣が床かを4ビットで判定し、露出側面を選ぶ。直線・内外角・端・孤立壁を同じ仕組みから組み立てる。斜めの接続も含む256近傍を描画検証する。
- 4位相×16露出パターン×2材質＝128 PNG。手作業で128点制作するのではなく、同じメッシュ生成器から一括出力する。各画像384px、実効タイル128px、床中心アンカー(192,192)、画像幅3マス。
- 別々に書き出した半透明エッジのサブピクセル継ぎ目は、不透明な材質の基底で埋める。透明穴チェックはこの基底を含む最終描画の確認であり、メッシュ一致は別途検証する。
- キャラ／道具との前後関係、任意の局所透過は前段階の描画順処理を再利用する。
- 壁を壊した後はライブマップで接続パターンを選び直す。追加生成・Blender起動は不要。

## 再現

```
blender -b -t 4 --python fushigi-wall-kit-v1/build.py
blender -b -t 4 --python fushigi-wall-kit-v1/verify_geometry.py
python3 -m http.server 8000 --bind 127.0.0.1
# 別の端末で
python3 fushigi-wall-kit-v1/check.py
```

`build.py` は `tiles/`・`wall-kit.blend`・`manifest.json` を再出力する。既存原画のPNGは加工・上書きしない。Blender 4.3.2 / Cycles CPU / 8 samples / Standard / RGBA。採用候補は同梱blendで確認でき、完全な再構築手順はスクリプトを正とする。原画パスとSHA256、書出画像のSHA256はmanifestに記録する。

## 結果と限界

`geometry-validation.json`：実際に作ったメッシュの隣接辺を、全マスク・全位相・隣のマスクの組合せで2,048組比較し、最大座標誤差0。`validation.json`：2材質×4位相×256近傍＝2,048描画、材質変更によるゲーム状態維持、実ピクセルで遮蔽／透過、壁の動的除去、通常移動での曲がり通路、縦画面、実セーブ分離を確認。MVPもALL OK。

部屋全体・手前・細い通路・縦画面を実画像で目視した。接続と差し替えの仕組みは成立するが、美術の完成ではない。2×2の模様反復、直線的な床際、孤立壁の垂直な四角さ、側面の材質の引き伸ばしは残る。角を丸める／輪郭を崩すには共有辺と斜め近傍を含む形状規則を拡張する。画像の再抽選で対処しない。

この試作は固定カメラ。視点の変更には再書き出しが必要。128枚の先読み約15MBは確認用途であり、製品採用時は必要材質だけの読込・アトラス化を検討する。既存の生成地形にも適用可能だが、本家の部品構成・カメラ・透過処理を再現したという主張ではない。

main反映・公開は未実施。通常起動の古庭は公開中の低壁・床ピッチ0.82のまま。

## 貼り方の調整（2026-10-23）

ユーザーの「そこまで見ないとわからない」に対応。形状・高さ・カメラ・光・元のPNGを固定し、材質の投影だけを変更した。

- 旧：上面は2ワールド単位で原画1セル、側面は別セルを各帯の高さへ正規化。場所と面で岩の密度が異なり、側面で縦方向に伸びる。
- 新：全ての面に同じ原画の右上セルを使用。世界座標のXY・XZ・YZへ2単位周期で投影し、面の向きの絶対値の4乗で混ぜる。高さを各帯で正規化しない。隣接パーツの投影座標も共通なので、側面をまたぐ密度を揃える。
- 原画の継ぎ目は向かい合う端の10%帯だけ混ぜる。初回の全体反転による繰返しは菱形の模様が目立ったため不採用とした。
- 全128枚のアルファを旧版とバイト比較し、輪郭が変わらないことを確認。新規生成0回。`mapping-validation.json` に結果。

[変更前後と孤立壁の拡大](mapping-comparison.jpg)、[手前の壁とキャラの比較](mapping-front.jpg)。実画面の `mapping-before*.jpg` は変更前を保存したもの。貼り方で岩の密度と側面の色を揃えても、元の絵に焼き付いた陰影・2マス周期の反復・メッシュの直線的な輪郭は残る。形状調整との切り分けを目的に、それらはこの比較では変更しない。

今回のMVPは初回に既存の矢の着地点チェックで失敗。テストの開始地点はランダムな生成階に依存し、周囲の床を作る処理も外周を除外するため、右側の飛距離を必ず確保する配置にはなっていない。ゲーム本体・投擲ロジックの変更はなく、確認後の再実行はALL OK。
