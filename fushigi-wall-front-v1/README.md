## 設計

- カメラ・光・元画像・三方向の材質投影は `fushigi-wall-kit-v1/build.py` から直接再利用する。
- 壁の北隣だけが床である場合（4ビット露出mask=1）、部屋の画面下側の縁として専用部品を使う。それ以外は既存の汎用部品を使う。全ロケーション・全方向の完成版ではない。
- 北西の斜め隣が床でなければ左の曲がり際、北東が床でなければ右の曲がり際、両方なら短い端、どちらも床なら中央部品を選ぶ。中央は3種を世界座標の決定的な規則で選び、高低・肩の位置を変える。ゲーム乱数は使わない。
- 中央3種・左・右・短い端の6形状×4位相×2材質＝48PNGを自動書出し。生成AIへ部品ごとに依頼しない。
- 平面上の輪郭を岩の内側へ最大約0.39マス引き込み、床側への張り出しは最大0.035マスに抑える。側面も同じ上端へつなぎ、根元から上へ段階的に傾ける。キャラの通行判定や論理マスは変えない。見えているくぼみは新しい歩行可能マスではない。
- 隣の汎用部品と接する左右・奥の端は旧形状と同じ座標へ戻す。共有端を変えず、露出する縁の内側だけを変形する。角の接続と形状の変化を両立させるための制約。
- 最初の細かな尖りが並ぶ案は実画面で柵状に見えたため不採用。幅のある岩の肩へ変更し、同じ形が一列に並ぶ反復も中央3種で減らした。

## 確認と再現

```
blender -b -t 4 --python fushigi-wall-front-v1/build.py
blender -b -t 4 --python fushigi-wall-front-v1/verify_geometry.py
# リポジトリをHTTP配信中に
python3 fushigi-wall-front-v1/check.py
```

Blender 4.3.2 / Cycles CPU / 8 samples / RGBA384px / タイル128px相当 / 原点(192,192)。部品のハッシュと輪郭のプロファイルは `manifest.json`、モデルは `front-parts.blend`。

実メッシュの左右端・奥側と汎用部品との一致は `geometry-validation.json`。ブラウザでは2材質×4位相×256周辺地形の描画、状態維持、実ピクセルの遮蔽／透過、壁の動的除去、通常移動の曲がり通路、縦画面・実セーブ分離を確認する（`validation.json`）。不透明な基底を含む穴チェックであり、接続の自然さは画像でも評価する。

部屋全体・手前・左端・右端を実画面で確認した。下辺を単純な直線から変えられたが、基盤の周期や縦壁の直線、角の床の直角は残る。左右端の部品は下辺側の入り込み形状であり、縦壁全体を丸めた汎用角モデルではない。上辺・縦壁・孤立壁の造形はこの試作の範囲外。次に広げる場合も方向ごとの役割を分け、汎用内部を作り直さない。
