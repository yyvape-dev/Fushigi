# 採用モックに基づく城下町・宿屋

ユーザーが街＋宿屋の生成モックを採用し実装を承認。追加指定：住民モーションは使い回し、傭兵の雇用は不要。

## 実装

- 城下町60×48（従来22×15、面積約8.7倍）。噴水広場、城門、閉じた民家、露店、傭兵広場、北東の洞窟入口。
- 宿屋「赤いマント亭」は別の屋内20×24。扉を踏んで出入り、寝室と受付の間を歩ける。クリア・死亡・脱出はいつものベッドへ。最初の方向入力でベッド脇に起きる。ベッドは一人用へ縮小し、体を切り取ったり布団へ埋めたりせず、全身の寝姿を上に重ねる。休息は無料。
- 鍛冶屋は屋外カウンター。武器・盾を＋1、上限＋9。料金は300＋100×現在の正の強化値G。神器・印・装備参照は維持。料金・上限は本作の初期調整。
- 預け屋は屋外カウンター。既存の道具・預金の保存を利用。道具売買は隣の露店へ分離。倉庫・預金は死亡後も残る。
- 住民・商人は既存店主の茶／藍／深紅8方向の待機・歩行を共有。ユズナミキ、アベニウス、シェリニーニャも既存待機／歩行アトラスを共有。住民の新規画像・モーション生成なし。ラナだけ布団の上で全身を横たえる静止画1枚を追加（アニメーションではない）。反転やコマごとの体型変更なし。
- 傭兵は街を歩いて会話するだけ。雇用UI・雇用料金・雇用状態なし。洞窟での既存ランダム遭遇・加入は維持。
- 住民は壁・噴水・他の人物・ラナを避け、ラナの隣で立ち止まる。UI表示中と非表示タブでは停止。街専用乱数で、戦闘・地形生成の乱数を消費しない。住民の待ち時間に世界ターン・空腹は進まない。
- 「街の地図」またはMで施設位置と現在地を確認。保存は既存v1の任意フィールド `town:{area,x,y,waking}`。既存セーブは宿屋へ移行し、冒険途中のセーブは従来のまま復帰。

## ファイル

- `../assets/castle-town.js`：地形判定、施設、住民、背景描画、町内の保存。
- `../assets/castle-town.css`：施設会話、街の地図、縦横画面。
- `../assets/town-v2/{town,inn}.webp`：本番背景。元画像の配置・色を保って圧縮。
- `source-art/approved-mock.png`：ユーザー採用モック。
- `source-art/{town,inn}.png`：人物と文字を分離して生成した本番原画。生成元は採用モックを毎回参照。
- `generation-record.json`：参照、用途、ハッシュ。`prompts.md`：生成プロンプト。
- `build.py`：PillowによるWebP再出力。背景は画像生成、コードは地形判定と人物の合成。

原画は1枚背景として保持。通行ポリゴンは画像内の石畳に合わせて登録し、室内家具・閉じた民家・噴水は通れない。カウンターの手前部分は同じ背景から重ね、既存の店主の足を隠す。

## 検証

リポジトリルートで以下を実行。

```
node tests/harness.js index.html tests/test_castle_town.js
node tests/harness.js index.html tests/test_mvp.js
node tests/harness.js index.html tests/test_run_save.js
node tests/harness.js index.html tests/test_allies.js
node tests/harness.js index.html tests/test_alternate_attack.js
node tests/harness.js index.html tests/test_dungeon_modules.js
```

静的サーバーを起動して `python fushigi-town-v2/check_runtime.py`。Playwright・Chromium使用。別のURLは `FUSHIGI_TEST_URL` で指定。自動操作はブラウザの新規コンテキストのローカル保存のみ。

施設への接続、民家と噴水の通行不可、住民の無衝突歩行と乱数分離、鍛冶の料金・上限・装備維持、倉庫・預金、街内保存と旧セーブ、クリア・死亡後のベッド復帰をテスト。実ブラウザで屋内外、縦横、会話、強化、預金、街の地図、再読み込み、画像読込、JavaScript例外を確認。

## 次の調整

街の歩く距離・住民密度・鍛冶料金は実機の遊び心地を見て調整。新規住民アニメーションの量産、民家内への侵入、傭兵雇用は今回の範囲に含めない。
