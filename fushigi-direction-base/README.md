# Fushigi：方向別スタート絵 v1

ゲームに収まる大きさと足元を先に決め、将来の武器・盾の別画像表示に備えた8方向の待機基準絵です。
**今回の成果物はスタート絵です。新しい歩行・攻撃アニメーションはまだ作成していません。**

## 見る順番

1. `preview.html`：画像内蔵の確認画面。方向・マスの大きさ・身長・仮の剣と盾・接続位置を切り替えられます。HTML単体でも表示できます。
2. `base-contact.png`：8方向を同じ縮尺・足元で並べた一覧。
3. `in-game-directions.png`：実ゲームの同じ位置で向きだけを切り替えて撮影した一覧。
4. `game-landscape.png` / `game-portrait.png` / `game-dungeon.png`：画面サイズと町・洞窟での確認。

ゲーム自体を動かす場合はこのフォルダーで `python -m http.server 8000` を実行し、`http://localhost:8000/game-base.html` を開いてください。
確認用コピーでは設定の「主人公の表示」を「基準絵」にすると新しい絵を使用します。移動・攻撃のゲーム処理は動きますが、身体の絵は各方向の待機1枚です。

## 固定した基準

- 画像：256×256 RGBA、方向順 S / SW / W / NW / N / NE / E / SE。
- 足元：(128,224)、頭頂の目標：y=32。頭頂〜接地基準まで192px。
- ゲームでの身長：初期設定で1.5マス。1マス64pxなら96px。
- 方向別に描き、左右反転を使わない。
- 武器を本人の右手、盾を本人の左手に持たせる。手の座標・描画の手前／奥を方向ごとに記録。
- 武器・盾を描き込まない握り手の待機姿勢。装備は独立した画像として重ねる。

詳しい座標規約は `BASE_CONTRACT.md`、機械可読データは `assets/hero-base/base.json` にあります。
足元は両足の接地を代表する点です。斜めから見た靴先の最下端と全方向で同じ点になるわけではありません。

## 絵の制作

8方向の同じ待機姿勢をBlenderでガイド化し、キャラ設定画と併せて生成しました。
最初の斜め後ろ2方向は真後ろに近かったため、角度を個別に生成し直し、頭と髪の比率も再調整した版を使っています。
生成絵を方向ごとに一様拡大縮小・平行移動して共通キャンバスに配置しました。身体のパーツを画像変形で動かしてはいません。
`generated-directions.png`、`generated-rear-final.png` が使用した生成画像、`overrides/` が後ろ斜めの差し替え元です。
`source-normalization.json` に切り出し・配置の情報があります。

## 装備の取り付け

`hero-base-renderer.js` は本体と装備を別々の画像として読み、以下の順で描きます。

1. 奥側の装備。
2. 本体。
3. 手前側の装備。
4. 近い右手の握り部分（武器の柄を握って見せる簡易前景マスク）。

座標は最初に3Dガイドから投影し、その後に生成絵の実際の握り位置へ手動で合わせています。
完全に隠れる遠い手の座標は推定です。方向に応じた粗い前後の重ね順までを今回検証しました。

`equipment-test/weapon.png` と `shield.png` は接続確認用の仮絵です。完成アートではありません。
特に盾は1枚を横に縮めた診断表示なので、正面／側面／裏面の完成画像が必要です。
元ゲームの持ち物・装備品とはまだ連動していません。確認用JavaScriptの `heroBasePreview` で明示的に表示します。
歩行・攻撃へ進む際はコマごとに手の位置、角度、握り手のマスク、前後関係を追加します。待機1コマの値を全動作で固定して使う仕様ではありません。

## 検証

- 全方向の画像寸法・透過・画像の切れを検査。
- Chromiumで町の実画像を読み込んだFushigi本体に表示。
- 48／64／96pxのマスで、8方向×2装備の柄・握り位置の座標一致を確認。計24パターン。
- 8方向の入力と画像の対応、方向切り替え時に足元が同じ描画座標に留まることを確認。
- 横画面844×390、縦画面390×844、洞窟で表示を確認。
- ブラウザ内JavaScriptエラーなし。結果は `browser-validation.json`。
- 元リポジトリのMVPテストも確認用HTMLに対して実行し、`ALL OK`。出力は `mvp-validation.txt`。この画面なしテストでは既存描画へのフォールバックを検証し、新しい基準絵の描画は上記ブラウザで検証しています。

数学的に装備の柄とソケットが一致することと、完成アートで自然に握って見えることは別です。今回は仮絵の位置と粗い前後関係を確認しています。
生成絵の細部と髪・髪飾りの位置には方向間の微差が残ります。カメラ角も生成画像上は近似です。

## ゲームへの適用

このフォルダーの `game-base.html` は取得したゲーム本体へのローカル確認用差し込みです。
元のゲーム本体は `game-original.html`、変更差分は `integration.patch`。
実リポジトリへ適用するときは `assets/hero-base/` と `hero-base-renderer.js` をコピーし、`git apply --check integration.patch` の後に差分を適用します。
元リポジトリはこの制作中に変更しておらず、push・GitHub Pagesへの公開はしていません。
同梱の既存町・アイテム等の画像はFushigiリポジトリから取得した確認用データです。

## 制作を再実行する場合

```sh
LP_NUM_THREADS=2 blender -b -t 4 --python make_direction_guides.py
python prepare_direction_sheet.py
# 生成画像・後ろ斜めの差し替え画像を配置した後
python prepare_base.py
python make_equipment_tests.py
python calibrate_sockets.py
python integrate_base.py
python build_preview.py
```

手の位置を再調整する場合は `calibrate_sockets.py` の値を更新します。
キャラの生成絵は参照用のマネキンに単純なテクスチャとして貼ったものではなく、ポーズガイドを参照して描き直した2D画像です。
