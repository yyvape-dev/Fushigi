# ダンジョン生成と描画の構成

## 区画方式の地形生成（2026-10-22・最新）

`assets/dungeon-generator.js` を、旧「ランダムな長方形＋中心から中心のL字通路」から**区画方式**へ置き換えた。マップは 56×32（`index.html` の `DW`/`DH`）。

- マップを 14×10 マス前後の区画（56×32 なら 4×3）に分け、各区画に「部屋」か「通路の曲がり角（ノード）」を置く。区画の縁2マスは空ける。
- 隣り合う区画を、部屋の壁の外側1マス（出入口）どうしでZ字の通路でつなぐ。通路は他の部屋を貫かず、壁に沿わない。
- 構成は3種：`chain`（蛇行する1本道。末尾を切り落として空白を作る）／`branch`（ランダムな全域木。端を一部切り落とす）／`loop`（木＋近道2〜3本）。
- 区画の端（行き止まり側）は必ず部屋。途中の区画は25%で曲がり角にする（部屋は最低5つ・区画の6割以上を保つ）。
- 部屋の形：長方形の外枠の隅を削り、L字（25%）・十字（20%）にする（計測では部屋全体の約15%）。外枠 `x,y,w,h` は変えず、`shape`（`rect`/`L`/`cross`）を追加。中心（階段・店の位置）が床でなければ長方形に戻す。出入口は床のある辺の行・列から選ぶ。
- `rooms` の外枠は長方形のまま（`x,y,w,h,cx,cy,role,shape`）。並び順はシャッフル済みで、`rooms[0]`＝開始部屋が毎回左上になることはない。追加の戻り値：`nodes`（曲がり角の座標）、`grid`（区画数）。
- 小さなマップ（幅32未満・高さ20未満）と、グリッド方式の失敗時は、旧方式（`legacyPlan`）に退避する。
- 配置（`index.html` の `newFloor`）：階段は開始部屋から**歩く距離**（`pathDist`）が最遠の7割以上の部屋からランダム。開始地点から歩いて8マス未満には敵を置かない。敵・アイテム・罠は部屋数に応じて増やす（部屋7つ基準。敵は最大14体）。

### 計測（`node tests/tools/dungeon_metrics.js 56 32 1000 --ascii=3`、1,000シード・事実）

| 指標 | 旧方式 40×25 | 新方式 56×32 |
|---|---|---|
| 部屋数（平均） | 6.9 | 8.6 |
| 部屋の壁に沿う通路マス | 10.1 | 0.0 |
| 通路の行き止まり | 0.0 | 0.0 |
| 通路の2×2の塊 | 3.2 | 0.6 |
| 3×3区画のうち部屋のある数（最大9） | 6.2 | 7.0 |
| 開始→最遠部屋の歩数 | 36.7 | 89.9（最大196） |
| 連結していない階 | 0 | 0 |

未解決・次の候補：`chain` は歩数が長い（最大196）。階全体のシード化（内容物は別乱数のまま）。洞窟状の部屋・柱。（大部屋は実装済み：8×5以上、約3割の部屋、平均2.6室/階。店が優先して使う）`distMap()` は敵AI用に90歩で打ち切る（到達確認のテストは上限なしの探索に変更済み）。

## 自然洞窟の本番画像（最新）

`assets/cave-terrain.js` と `assets/dungeon/cave-v1/` を本編で使用。画像生成で制作した穏やかな床3原画・自然岩壁上面／正面・下り階段を適用した。床の共有境界、壁の内外角・通路接続は原画と地形マスクを組み合わせて描画する。壁256接続・床3色調の共有境界・40生成階・縦横表示を検証。旧石造り画像は比較用の制作履歴。詳細と原画・プロンプト・再現手順は [ダンジョン画像制作](../fushigi-dungeon-art-v1/README.md)。以下の石材初版・角素材未対応という記述は前段階の記録。

## ゴール

風来のシレン型の、部屋・通路・探索・ターン制戦闘・資源管理・特殊部屋が組み合わさるダンジョンを目指す。固定の1部屋や3D模型を完成扱いにしない。3Dは地形画像を制作する工程で、本編は正方形タイルのCanvas描画を使う。

## ランダムにする範囲

| 層 | 現在の実装 | 守る条件 |
|---|---|---|
| 地形 | 40×25、部屋の数・寸法・位置、直列・枝分かれ・環状の接続、曲がる幅1マス通路 | 全床が接続、外周は壁、部屋と通路の寸法を維持 |
| 部屋の役割 | 開始、階段、通常、魔物部屋、店部屋 | 開始・階段・魔物・店の役割を重ねない |
| 見た目 | 石材3色調、4床差分、壁正面・壁上面、地形に合わせた影 | 当たり判定を変えない。描画ごとに模様を再抽選しない |
| 内容物 | 深度別の敵種類・敵数、道具、お金、罠、階段、魔物部屋 | 既存の階層別抽選・視界・角抜け禁止を維持。店の初期配置と重ねない |
| 店 | 2階から25%で候補部屋を選択、階層に合う品ぞろえ、既存の買う・売るUI | 町の倉庫・預金・在庫と分離。在庫は同じ階で開き直しても保持 |

地形と外観は独立モジュール。現時点で外観は同じ石造素材の色調・床差分であり、自然洞窟・遺跡・水辺の専用原画を作り終えたという意味ではない。地形はシード再現可能。敵・道具・罠・店は既存の乱数処理で抽選するため、地形シードだけでは階全体の内容物は再現しない。

## 実装場所

- `assets/dungeon-generator.js`：地形・接続構成・石材テーマ・床差分シード。
- `index.html`：既存の戦闘・配置・部屋の役割・店の売買への接続。`placeDungeonShop()` は開始・階段・魔物部屋を避け、その部屋の通常配置を除いて店を設ける。
- `assets/dungeon/`：Blenderから書き出した床4枚・壁2枚。角や接続は既存の隣接判定と影を使う。
- `assets/approved-hero.js`：承認済みキャラ・武器12種・盾10種の読み込みと所持品連動。v3レンダラーを再利用し、原画は変更しない。
- `fushigi-dungeon-v1/random-review.html`：最新本編の生成・描画・配置を使う確認画面。別の階の生成、装備交換、攻撃、全体地図。セーブ読書きを無効にして本編の持ち物を保護する。
- `fushigi-dungeon-v1/preview.html`：最初の7×5部屋＋通路の寸法確認。最新本編から再生成し、旧キャラ表示を修正。

## 承認済みキャラ・装備

全8方向の基準絵と300msの6コマ攻撃を本編で使用する。左右反転をせず、攻撃中は開始方向を固定。武器0.66、盾0.59、NWは盾が身体より後ろ、SEは手より前。盾10種類のSEは専用quarter-se原画を使う。所持品の種類に合わせて装備画像を切り替え、未装備なら表示しない。

カタログ外の初期アイテムである木の棒・大斧・木の盾は従来の個別画像を保持し、鉄の剣・鉄の盾はv3の基準装備を使う。木の盾の向き別原画と木の棒・大斧の新規承認原画は今回追加していない。歩行は8方向の基準絵を移動させる方式で、歩行専用コマは未制作。

## 次の工程と未実装

現在の店は部屋内でメニュー売買できる初版。床の商品を拾う・未払い管理・店主・泥棒・追跡は未実装で、シレンの店の仕様を完成したとは扱わない。自然な岩形状、専用内外角・出入口画像、床の装飾、変形部屋、水・壁掘り等の地形ギミックも次の工程。

次は専用の角・出入口素材と自然洞窟の表現を少数作り、実際のランダム生成全体で接続を確認する。店は商品・会計・店主を別モジュールにして発展させる。新規素材を大量に作る前に、本編上の少数例で寸法と遮蔽を確認する。
