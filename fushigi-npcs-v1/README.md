## 本作で補った仕様

- ユルサの「通常＋1」は明記がなかったため採用した初期値。大成功は1回の抽選で、武器と盾に共通の＋3。装備が片方だけでも利用可能。装備がない・全て上限・未精算だけなら機会を消費しない。
- 2階以降、各階24%で1人、3人を等確率で抽選。通常の部屋の開けた床だけに配置。店・魔物部屋・階段部屋・出入口・狭い通路を避ける。候補がない階は出現しない。既存の同行者の遭遇とは独立。
- 同行も戦闘もしない、待機するNPC。サービスは各遭遇1回。断った場合は再度話せる。会話とサービスは世界ターンを進めない（既存の仲間会話と同じ）。
- 交換条件は出現時に決定。断る・再読込では再抽選しない。要求品は現階で出る一般品から選び、見返りは復活の草／無敵草／全滅の巻物／火迅風魔刀／回復の剣／見切りの盾／合成の壺／強化の壺から抽選。要求品を未所持でも、後で持参できる。
- 未精算品と外せない呪われた装備は交換不可。同じ品を複数持つ場合は未装備を優先。保存の壺の中身も渡せる。装備しかない場合は、外れることを表示する。
- 報酬の置き場を先に確保する。手持ちの要求品を渡す場合は空いた枠へ受領。満杯なら歩いて3マス以内の空いた床（店・罠・他の人物を除外）へ置く。場所がなければ道具・サービスを消費しない。
- 既存の途中保存に任意の `npcs` を追加。人物・使用済み・要求品・見返り品・報酬との参照関係を保持。古い保存はNPCなしで復元。

## 制作

- ゲームのロジックとUI：`assets/dungeon-npcs.js` / `.css`。
- 新規画像：`assets/{yursa,kamil,ialmas}/{S,SW,W,NW,N,NE,E,SE}.png`（このフォルダ内）。256×256 RGBA、頭頂から足元192px、足元原点(128,224)。既存主人公と同じ描画倍率、65°固定の床投影を使用。
- 元生成画像 `source.png` は保持。ユーザー添付3人＋採用済み主人公 `fushigi-direction-base/assets/hero-base/S.png` を参照し、同時に24待機絵を生成。会話時に向くだけのため、歩行・攻撃モーションは作らない。
- 再出力：`python fushigi-npcs-v1/build_sprites.py`。実際のマゼンタの隙間で6行を切り出し、背景をキー処理、等倍比率で足元を揃える。初回の均等行分割では次の行の頭が混ざったため、原画の隙間に合わせた行境界へ修正。原画自体は改変しない。
- `sprites.json` に原画と全24画像のSHA256・寸法・領域を記録。`contact-sheet.png` は採用24方向の確認。
- 生成プロンプト：添付3人の特徴を維持し、採用済み主人公と同じ約2頭身・厚塗り・65°見下ろしへ。ユルサ＝金髪と黒帽子、赤い襟巻き、革の鍛冶服と右手のハンマー。カミール＝長い灰緑髪のエルフ、白と青緑の治癒士の衣。イアルマス＝黒いフードと鎧、左腰に帯刀した侍。各8方向、4列×6行、背景#FF00FF、床影・文字・兎なし。装備・非対称な衣装を反転で代用しない。
