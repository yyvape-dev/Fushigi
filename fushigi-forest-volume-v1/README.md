# 灯祭りの森：木と照明の立体モデル化

ユーザー指示：「木の幹・枝・樹冠とランタンを立体形状に置き換える」。3D表示の木・ランタン・連灯を、ビルボードから実際のメッシュに置換する。

## 形状

`assets/forest-models3d.js` の `buildForestModels` が本編・確認ビュー共通の形を作る。

- 幹：頂点を曲げた先細りの柱。
- 枝と根：端点を結ぶ先細りの立体。
- 樹冠：凹凸を付けた厚みのある塊を4つ重ねる。木ごとに枝の角度と葉色を地形座標から変える。
- ランタン：六角形のガラス、上下の枠、6本の支柱、円錐の屋根、金属の吊り輪と取り付け腕。木が無い配置には支柱も立てる。
- 連灯：少したわむ立体ロープ、短い吊り紐、金属キャップと球形の灯り7個。

3D装飾に `PlaneGeometry`・`Sprite`・カメラ向きの回転は使わない。木の幹・枝・葉や金属は照明を受け、影を落とす。ガラスの発光と球形の灯りは形状を保ったまま発光表現を行い、近いランタン最大6灯が地面を照らす。弱い青い方向光を追加し、主人公の光から離れた樹冠でも丸みが読めるようにする。

最大12種類の形状をインスタンス描画でまとめる。既存の樹皮・葉のWebPを材質に流用し、新しい生成画像は作っていない。今回のPNGは3Dを実際に描画した確認画像。

## 維持する仕様

- ランダム地形と `ForestFestival.plan` の装飾配置は変更しない。
- 根・幹・ランタン支持部は壁マスに収める。樹冠は厚みを持つため少し張り出すが、通行判定を追加しない。
- 階段周囲の空き、細い道に連灯を置かないこと、階の再読み込み時の同じ配置を維持。
- 主人公・敵・道具は既存の2D描画のまま。2D表示の森も既存の画像を維持。
- 他ロケーションの地形・照明・モデルは変更しない。
- スマホ実機性能は未計測。「影なし」「2D」の既存切り替えを維持する。

## 確認ビュー

`preview.html` は本編と同じモデル生成関数を使い、45°・65°・85°と横方向の回転を確認できる。製品のカメラ操作やセーブには接続しない。

```sh
python3 -m http.server 8878 --bind 127.0.0.1
# 別の端末で（Playwright + Chromiumが必要）
python fushigi-forest-volume-v1/check_browser.py
bash tests/run_all.sh
node tests/check_art.js
```

ブラウザ検査はモデルに平面・スプライトが無いこと、各形状にXYZすべての厚みがあること、同じ配置から同じ変換行列ができること、必要な部品・木の落ち影があることを確認する。さらに30 seedの本編3D、影ON/OFF、他4ロケーションへの切り替え、縦画面と2D復帰を確認する。

`validation.json` は検査結果、`models-*.png` は角度の違う同じモデル、`game-*.png` は本編の実画面。実画面の撮影時は、元から存在するランタン近くの通れる床へ主人公を移した。地形は変更していない。

## 検証結果

- `FOREST SOLID MODEL CHECK OK`：30 seed、最大12形状バッチ。部品に平面・スプライトなし、XYZの厚み、同じ変換行列、幹・枝・葉の落ち影を検査済み。
- ランダム地形の入力不変、影ON/OFF、他4ロケーションへの切り替え、2D復帰、縦横画面を確認。ページ例外なし。
- `bash tests/run_all.sh`：全33本が初回成功、`ALL TESTS PASSED`。
- 描画確認はChromium/SwiftShader。三角形数やバッチ数は記録しているが、スマホのフレームレートを保証するものではない。
