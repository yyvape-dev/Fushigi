# 根絡みの古庭：追加ロケーションの試作

`index.html` が確認画面。リポジトリを HTTP 配信してこのフォルダを開く。
本編と同じ地形・操作・キャラを使い、同じ階で「新しい古庭」と「従来の遺跡」を切り替えられる。「別の部屋」「別の階」「マス境界」で配置と判定を確認する。

既存5ロケーションの自動巡回にはまだ加えていない。追加候補は `DungeonGenerator.locations`、既存巡回は従来の `DungeonGenerator.themes`。新ロケーションの描画だけ `assets/overgrown-garden.js` に分離し、既存の描画へはそのまま委譲する。

## 今回試したルール

- 部屋の座標・地形の描画シードから、根／苔／崩れ石の主題と主役になる壁を選ぶ。
- 一部屋を一つの連続した絵として合成し、壁際から広がる濃淡と群生を作る。タイルごとの独立抽選はしない。
- 中央、出入口、階段、通路、店舗床を空ける。保護する部分へ近づくにつれ装飾を薄くし、マス境界で絵が突然切れないようにする。
- 根は専用生成画像2種を壁側から室内へ向ける。苔と小石も専用の透過生成画像を同じ部屋のまとまりに従って置く。コードで植物や小石の絵を描かない。すべて平面の装飾で、障害物・取得アイテムにはしない。
- 壁全体は0.24マスの一定高。同じ高さの上面を連続させ、壁同士の内部境界には側面や縁取りを出さない。床に面する部分だけに縁と側面を出す。専用生成画像は輪郭を持たない不透明な材質で、既存画像の欠けや飛び出した石を流用しない。移動・角抜け・視界のルールは変更しない。
- 地形・役割の変化で合成キャッシュを無効化する。大砲で床になったマスはライブの地形と部屋所属から描画し直す。
- 床は3マス、壁上面は4マスで材質をつなぐ。材質の対向する端だけを描画時にブレンドし、共有境界の継ぎ目を抑える。

## 専用の生成原画（2026-10-23）

`source-art/garden-materials.png` は専用の床／壁上面／壁側面／苔のある床の4区画。`source-art/garden-decals.png` は根2種／苔／崩れ石の透過4区画。いずれも画像生成ツールで制作した1254×1254画像で、生成出力から変更せずコピーしている。シートは各627×627区画をCanvasで参照し、根・苔・崩れ石の形を手描きコードで代用しない。床・壁の色や石材も今回の専用原画へ差し替えた。階段と画面外の天井は既存の遺跡素材を再利用している。

正確な生成プロンプトと用途は `generation-record.json`、寸法・透過・SHA-256は `source-art/manifest.json`。原画はリポジトリ外の `/workspace/generated_images/` にも残している。通常プレイの既存ロケーションでは新原画をロードせず、古庭の初回描画か確認画面で取得する。

部屋の合成は1マス96pxで保持し、横画面でも生成画像の細部が粗く拡大されないようにする。合成キャッシュは部屋オブジェクトに弱参照で結び、古い階を保持し続けない。

確認画面では全localStorageをフレーム内のメモリへ差し替える。本編の冒険保存、町の保存、設定やページ離脱時の保存に触れない。確認画面を再読込すると初期状態へ戻る。
